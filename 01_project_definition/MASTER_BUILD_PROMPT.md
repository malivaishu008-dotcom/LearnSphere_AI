# LearnSphere AI — Master Build Prompt

```text
Act as a principal product designer, staff full-stack engineer, learning-science researcher, and AI safety lead. Build LearnSphere AI, a premium, accessible, responsive study operating system for students. It is an AIML internship product of CHATAKE INNOWORKS PVT. LTD. / MINDFORGEAI Division.

Outcome: a real dynamic web platform—not a static mockup—where a learner can create subjects, plan tasks and timetable blocks, upload PDFs/books/content and voice notes, write notes and diary entries, run MCQ/quiz/surprise-test practice, review study consistency, and see clearly labelled indicative mark scenarios with actions to improve.

Design language: restrained, high-trust academic software; deep ink/navy, warm paper, electric lime for progress, violet for intelligence; Manrope-like typography; generous whitespace; strong information hierarchy; polished header/footer and mobile layout. Include original favicon, SEO metadata, empty states, error states, loading states, keyboard-visible controls, and an accessible contrast baseline.

Technical standard: use a maintainable full-stack architecture, persistent data store, authenticated API, validation, protected upload handling, environment-based configuration, tests, Docker/deployment assets, README, architecture diagram, user stories, data model, API contract, contribution policy and a professional report. Keep personal user uploads and secrets out of git.

AI standard: use a provider adapter and document-grounded workflow. Do not request personal ChatGPT, Gemini, Google, or NotebookLM passwords. Support server-side API-key configuration or official OAuth. Show consent before sending student material externally. Clearly label generated content, learning predictions, uncertainty, and limitations. Keep a useful non-AI fallback.

Build in phases: (1) foundation and landing, (2) student workspace and knowledge base, (3) practice and planning, (4) insights and diary, (5) AI/provider integrations, (6) security, deployment and evaluation. Ship a working local MVP at every phase and document what is real versus roadmap.
```
